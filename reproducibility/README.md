# Compost manuscript analysis archive

This directory archives the computational analyses supporting **Data auditing and group-aware machine learning for interpretable compost maturity screening**, prepared for the Journal of Environmental Informatics. It extends the P1 Streamlit prototype with P0/P0+EC/P1 comparisons, day-removal ablations, Segment A controls, P1 split-conformal calibration, P1 SHAP, model comparisons, and statistical figure and table scripts.

The archive contains the exact analysis workbook, a processed table, fixed reference results, portable scripts, dependency versions, and verification reports. The provisional field remapping and batch-proxy grouping reproduce the manuscript's assumptions; they do not resolve the missing original study identifiers or independently establish the field mapping.

## Run the analyses

Use Python 3.12 in a separate environment. The dependency file below is for the manuscript analyses; the repository-root `requirements.txt` remains the deployment environment for the app.

```console
python -m venv .venv-analysis
# Activate this environment using your operating system's usual command.
python -m pip install -r reproducibility/requirements.txt
python reproducibility/run_analysis.py --stage core
python reproducibility/run_analysis.py --stage models
python reproducibility/run_analysis.py --stage targets
python reproducibility/run_analysis.py --stage regularisation
python reproducibility/run_analysis.py --stage tables
python reproducibility/run_analysis.py --stage figures
```

Alternatively, `python reproducibility/run_analysis.py --stage all` runs all stages in that order. Computation time depends on the machine. Generated files are written below `reproducibility/generated/`; use `--output PATH` to select another output directory. Run the computational stages before the figure/table stages when using a fresh output directory. `--stage audit-figure` renders only the four-panel calibration/ablation/SHAP diagnostic corresponding to current Fig. 4, after `core`.

The `core`, `models`, `targets`, and `regularisation` stages explicitly refit their models. `core` removes only its generated P1 SHAP cache before recomputing SHAP. Numerical outputs are compared with the archived reference results at an absolute and relative tolerance of `1e-6`; the command exits unsuccessfully when comparisons fail, and writes details to `verification_<stage>.json`. Reference values are never overwritten. Plotting stages reuse results generated by earlier computation stages.

## Data and validation design

The workbook is from [1191600618/Compost-Dataset](https://github.com/1191600618/Compost-Dataset), fixed at commit `ba42c3d617169a5e52345ce1d02c49bcfe1b416d`. Its checksum is verified before every run. Parsing yields 4,248 valid records, including 2,571 GI-labelled records in 326 proxy groups. Dataset attribution and license are retained in `data/`.

P0 contains eight inputs, P0+EC nine, and P1 fourteen. Models use split seeds 0, 7, 21, 42 and 84, with 25% held out for testing. The random split stratifies on GI quantiles; group splitting uses the initial-condition proxy. Preprocessing is refitted inside each training split. Fixed estimator settings are available in `model_library()` and exported to `generated/tables/TableS2_model_parameters.json`.

Conformal analysis uses P1: an outer proxy-group split reserves 25% for testing, and an inner proxy-group split reserves 25% of the remaining pool for calibration, using seed + 1000. The archived routine retains its finite-sample empirical-quantile convention. P1 SHAP uses the representative proxy-group split with seed 1. The core run exports full-data P0 and P1 research models separately; these are refits on all GI-labelled records, not validation models. Only load model pickle/joblib files from a trusted source.

## Reproducibility boundaries

The computational analyses and reference results are archived with the following scope:

- **Fig. 5g–l regularisation experiment:** its recovered fitting script and original split-level results are both included. In this experiment, estimator random seeds vary with split seeds; the main nine-model screen instead fixes estimator seed 1. This explains why the `XGB_current` results are not identical to the main-screen XGBoost results. Run `--stage regularisation` before plotting these panels.
- **Figure numbering and presentation:** Fig. 1 is the data-audit and field-calibration plot generated by `fig1_data_audit`. Fig. 9 is a screenshot of the research prototype; the app source remains in the repository root. Statistical scripts retain historical panel labels and layouts; see `figure_map.csv` rather than interpreting historical filenames as current manuscript numbering.
- **P0 interpretation:** the paper does not report P0-specific SHAP or conformal calibration. The archived P1 results must not be relabelled as P0 results.
- **Source reconstruction:** original study/experiment IDs and bioassay protocols are absent from the workbook. The 1,662-record field remapping is provisional. Re-running these scripts verifies computations conditional on those choices; it does not establish their scientific validity or external generalization.
- **Exploratory selection:** model selection and assessment reused repeated holdouts. The earlier tuning scripts and regularisation results are exploratory and are not nested external validation.

Use the immutable Git commit of this archive when citing it. Verification reports identify which stages were actually executed and whether their numerical comparisons passed. No manuscript DOCX files or private review comments are included in this repository archive.
